# Community entry points

Use the [public issue tracker](https://github.com/LibreEvolve/libreevolve/issues)
for non-sensitive preview questions, reproducible bugs and permission-cleared
experiment reports. Search existing issues before opening another.

The repository includes three issue forms: bug, question and experiment. They
are proposed source files until present on the default branch; a draft pull
request does not activate the issue chooser. Blank issues remain available.
Forms do not assign people, create labels or enable Discussions.

Start with the [quickstart](alpha-quickstart.md), read the
[artifact contract](run-artifacts.md), and use the [development guide](development.md)
for contribution checks. A seed-only check is not optimization or provider-access
evidence. Unchanged and unsuccessful outcomes are welcome when accurately labeled.

Keep run completion, candidate validity, retention, same-corpus comparison and
usage completeness separate. Do not turn unknown usage into zero cost or expose
held-out results as a tuning target. Publish source or artifacts only when you
have permission to share them with the issue's audience.

Never post credentials, OAuth files, account details, raw prompts, complete run
directories or private candidate source. These forms are not a private security
or conduct-reporting channel. Follow a repository security policy if one is
available; do not disclose sensitive details publicly when no private channel
has been established.

Discussions are a separately configured platform feature. Proposed categories
or templates do not create them. No response deadline or paid support service
is promised by these entry points.
