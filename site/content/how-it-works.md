# Change code. Check the result.

The engineering preview searches bounded changes to a small Python bin-packing
heuristic with Codex OAuth. It does not optimize arbitrary repositories or
promise improvement.

## 1. Start with a seed

Initialize the bundled task and inspect its intentionally simple seed. Offline
preflight and a seed-only run make no model request. Use the canonical
[quickstart](../../docs/alpha-quickstart.md) for commands and limits.

## 2. Search for a change

Only after authorizing live subscription use, run the bounded Codex lane.
Candidates are checked by the task's evaluator. Local call/runtime limits do
not guarantee a token or dollar cap, or stopped remote billing.

## 3. Inspect what survived

A completed run is not the same as a valid or retained candidate. Read the
[result guide](../../docs/results.md) and [saved artifacts](../../docs/run-artifacts.md).
Keep training quality and held-out checks separate. Freeze selection before
held-out reporting; do not use that reporting set to tune the search.

## 4. Check before using or sharing

Local reports and verified exports perform fresh checks in host-access
subprocesses. They are not a security sandbox or universal correctness proof.
[Sharing](../../docs/share-export.md) is a separate opt-in workflow: review a
frozen allowlisted record before rendering local static files. Rendering a
frozen record does not execute candidate code or upload the result.
